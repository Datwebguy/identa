Vendor onboarding that checks before it retries.

Identa adds each company to a vendor register as one GitHub pull request. If the process dies mid-way, it asks GitHub what actually happened before it does anything again, so a crash does not turn into a second vendor record.

Crash test: protocol versus control

Each run onboards the same nine companies and kills the process once, at one of three points. The protocol reconciles with GitHub on restart. The control is the same code without the reconciler, retrying blindly. Counts are read from GitHub after each run.

How it works

Every action gets a stable identity, sha256(company_id, action, args), and the branch name is built from it. The same company and intent always produce the same branch, so the reconciler can look it up exactly.

1

Intend

Write the intent to a local store before touching GitHub: company, key, branch and planned steps.

2

Act

Create the branch, commit vendors/<id>.yaml, open the pull request. Each step is logged. Writes run one at a time.

3

Reconcile

After any interruption, read the exact branch, file and pull request on GitHub, then decide.

Reconciliations

Time from the saved record of the last write before the interruption to the reconciler's final check, read from evidence timestamps. Crash times include the container restart.

Business plan

Built in cfo.ai from two kinds of input. Costs come from real runs. Pricing and growth are the founder's decisions, not measurements.

Traces in neatlogs

Every run sent a trace. A killed process leaves a short trace whose last span is the write it finished, followed by the restart's trace, which starts by reading the branch on GitHub. No model is called, so tokens and model cost are 0.
